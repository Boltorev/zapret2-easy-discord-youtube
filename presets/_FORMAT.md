# Формат пресета

Один пресет = один файл `presets\<ИМЯ>.txt`. Все пресеты запускаются **одинаково**:
`core\Preset.ps1` читает файл, собирает аргументы и передаёт их `winws2.exe`.

```
[meta]
name  = AUTO
title = Авто (сам подбирает стратегию)
desc  = Краткое описание для меню
[args]
# комментарий, строки с # игнорируются
--wf-tcp-out=443,80
--lua-init=@{ROOT}\lua\zapret-lib.lua
--filter-tcp=443
--filter-l7=tls
--out-range=-s34228
--lua-desync=fake:blob=fake_default_tls:tcp_md5
--new
--filter-tcp=80
--lua-desync=multisplit:pos=midsld
```

## Правила

- `{ROOT}` заменяется на папку сборки (там, где лежат `bin\`, `lua\`, `presets\`).
- `--new` начинает новый профиль мультистратегии. Всё до первого `--new` — это профиль 1.
- Токены разделяются пробелами. **В значениях не должно быть пробелов** —
  поэтому и запрещён путь установки с пробелами.
- Парные кавычки вокруг токена снимаются (можно писать `--hostlist="{ROOT}\lists\x.txt"`).
- Комментарии — только целой строкой, начиная с `#`.

## Почему не `--wf-...` в one-line, как в .bat у Flowseal

Батники Flowseal собирают одну длинную строку с `^` и подстановкой `%LISTS%`.
Это ломается на кодировках, кавычках и `!` в путях. Мы держим аргументы
построчно, а `.bat` остаётся тонким лаунчером, который зовёт PowerShell.

## Проверка пресета перед запуском

Не требует прав администратора:

```powershell
. .\core\Common.ps1; . .\core\Preset.ps1
$p = Read-EasyPreset general
Test-EasyPresetFiles $p
Test-EasyPresetDuplicateLists $p
```

Требует администратора (манифест winws2 — `requireAdministrator`):

```
winws2.exe --dry-run <аргументы пресета>
```

> `--dry-run` проверяет **только** параметры командной строки и наличие файлов.
> Корректность Lua он НЕ проверяет. Реальная проверка — запуск с `--debug`
> и чтение лога (`core\test-runner.ps1`).
