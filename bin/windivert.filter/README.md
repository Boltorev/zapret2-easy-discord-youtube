# windivert.filter — фильтры отсечения в ядре

Смысл: WinDivert не умеет ограничивать перехват «первыми N пакетами» соединения
(в iptables это `connbytes`, в nftables `ct packets`). Если перехватывать порт целиком,
весь поток идёт через userspace — при просмотре видео это загрузка ядра и вой кулеров.
Поэтому полезную нагрузку отсекаем **в ядре**, а точную дофильтрацию делает winws2.

Подключаются через `--wf-raw-part=@{ROOT}\bin\windivert.filter\<файл>`.
Частичные фильтры объединяются **по ИЛИ**; их можно комбинировать с `--wf-tcp-out` / `--wf-udp-out`.

Язык фильтров WinDivert: <https://reqrypt.org/windivert-doc.html#filter_language>
В нём **нет** побитовых операций, сдвигов и логики по битовым полям, поэтому фильтры
намеренно «шире» реальности — лишнее отбросит winws2.

> В файлах фильтров **нельзя** писать комментарии: язык фильтров их не поддерживает.
> Всё объясняется здесь.

## Зачем нужен `windivert_part.quic_longheader_in.txt`

Оркестратор `circular` для UDP-профиля считает неудачу по условию
`udp_out >= N и udp_in <= M` (см. `standard_failure_detector` в `lua/zapret-auto.lua`).
Чтобы `udp_in` вообще рос, нужно перехватывать **входящий** поток. Но входящий QUIC —
это в первую очередь видеоданные (short header), и гнать их все через userspace нельзя.

Решение: перехватываем входящие только с **long header**. У QUIC long header
признак — старшие два бита `01` в первом байте, а вместе с обязательным fixed bit
(QUIC v1) допустимые значения первого байта для long header — `0xC0..0xFF`:
Initial `0xC0–0xCF`, 0-RTT `0xD0–0xDF`, Handshake `0xE0–0xEF`, Retry `0xF0–0xFF`.
Short header (1-RTT, то есть видео) имеет первый байт `0x40..0x7F` — он в фильтр
**не попадает**. Битовых операций для этого не требуется, достаточно `>= 0xC0`.

Проверка `udp.PayloadLength>=20` отсекает пустые/обрезки.

Итог: в счётчик входящих попадают только рукопожатие и служебные long-header пакеты —
этого достаточно детектору, чтобы отличить «сервер отвечает» от «сервер молчит»,
и при этом видеопоток в userspace не заходит.

## Ограничение v1.0.7

Максимальная длина итогового windivert-фильтра снижена с 64K до **16K**.
При сборке профилей держим набор `--wf-raw-part` компактным.
Проверить фактический фильтр: добавить `--wf-save=<файл>` — конструктор запишет итог.
